# Domain docs

This project uses one root `CONTEXT.md` for domain vocabulary and `docs/adr/` for decisions.

## Before exploring code

1. Read `CONTEXT.md` if it exists.
2. Read the ADRs in `docs/adr/` that concern the area being changed.

Continue when either is absent. The domain-modeling workflow creates them when vocabulary or decisions are resolved.

## Applying domain context

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. Record a missing concept as a gap for domain modeling when it belongs to the project's vocabulary.

When a proposed change conflicts with an ADR, identify the decision and explain why it should be reopened.
